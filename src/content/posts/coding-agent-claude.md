## 阅读边界

Claude Code 有公开仓库、插件和官方文档，但不能据此认定完整产品内部源码均已公开。本篇依据官方文档解释对外提供的行为，不将内部函数、执行顺序或闭源实现写成已验证源码事实。[官方工作方式](https://code.claude.com/docs/en/how-claude-code-works)

## 一个任务如何推进

官方文档把使用过程概括为收集上下文、执行动作和验证结果；这些过程可以反复交替。例如修改代码前先读取文件，随后应用编辑，最后运行检查。它描述的是产品行为框架，具体某次调用顺序由任务、配置和工具结果决定。

## 权限和沙箱分别约束什么

官方权限文档介绍针对工具及参数的规则和模式；沙箱文档讨论执行环境的限制。理解时可以先问两个问题：这次动作是否被允许？允许之后进程能够访问什么？规则配置、系统平台与具体执行环境都会影响答案。[权限配置](https://code.claude.com/docs/en/permissions) · [沙箱文档](https://code.claude.com/docs/en/sandboxing)

不要把“提示用户确认一次”理解为所有后续操作都安全，也不要假设沙箱一定能够覆盖每种运行环境。上线或团队使用前，应按官方文档检查适用平台和本地设置。

## 扩展与上下文

官方资料提供 hooks、技能、MCP 等扩展入口；它们分别需要结合具体文档理解触发条件、输入输出与权限。把某个扩展加载进产品，不等于验证它永远正确或适合生产。[Hooks 文档](https://code.claude.com/docs/en/hooks)

## 可以做的实验

选择一个无副作用的小仓库，记录任务输入、实际工具动作、权限提示与检查结果；再更改一项配置重复实验。实验能证明的是该版本、该配置下观察到的行为，不能推导全部内部实现。


## 先解释：为什么这篇不是逐函数源码解析

用户能在 GitHub 上看到项目仓库，不等于仓库一定包含完整产品内部源码。对本次研究，我核对了官方仓库入口和 Claude Code 文档；没有取得可与当前产品一一对应的完整内部源码。

因此下文区分官方文档陈述、可验证的使用行为与本文提出的实验方法，不猜测闭源函数的调用链。

## 工作过程：用一个修改任务拆解

官方[工作方式文档](https://code.claude.com/docs/en/how-claude-code-works)将过程概括为收集上下文、采取行动、验证结果。以“修复测试失败”为例，可能出现：读取测试和相关文件 → 判断需要修改的位置 → 执行编辑 → 运行测试 → 阅读失败输出并继续调整。

这只是说明三类活动如何交替，不是承诺产品总是按这五步执行。观察一次真实任务时，要记录产品版本、任务提示、项目配置和工具权限；否则不同实验的结果难以比较。

## 权限：规则如何影响一次操作

官方[权限文档](https://code.claude.com/docs/en/permissions)描述了工具权限、模式及允许/询问/拒绝等规则。面对一次文件修改或命令执行，可以分别检查：当前模式是什么、是否存在匹配规则、规则来源于哪个配置层级、当前用户是否已经授权。

例如同一条命令在两个工作目录下可能涉及不同文件。判断权限时不能只看命令名，还需要参考官方文档规定的匹配规则和实际环境。本文没有在不同操作系统上逐项验证所有规则组合。

## 沙箱：执行隔离还要检查哪些条件

官方[沙箱文档](https://code.claude.com/docs/en/sandboxing)介绍了相应的执行隔离机制和配置。实际使用中，应先核实操作系统与工具是否受支持，再明确允许访问的文件范围、网络和凭证，以及未启用沙箱时的行为。

权限规则和沙箱都应以官方当前说明及实际配置为准；本文不声称默认设置适合所有团队，更没有对其安全性进行渗透测试。

## 设计一组自己能复现的实验

选一个无敏感信息的临时项目，分别执行只读检索、修改文件和运行测试；记录每步是否出现权限提示、输入输出及用户确认结果。然后只改变一项配置重新运行，比较差异。遇到网络访问或外部写入时，先用可控测试服务，避免把副作用混进实验。

实验结果要写成“某版本、某配置下观察到……”，并保留原始记录；它不能证明未公开代码的确切结构，也不能代表其他版本。


## 实验记录模板

如果之后要补充自己的实测，至少为每次实验记录：产品版本、操作系统、工作目录、权限模式、相关设置、输入任务、用户确认动作、观察到的工具调用及结果。同一个案例只修改一个条件，才能较清楚地比较差异。

例如研究权限提示时，可以在临时目录中分别观察读取文件与修改文件；但不能因为某次没有弹出提示，就推断该操作在所有设置下都无需授权。当前文章没有执行这组实验，官方文档也是可能随版本更新的资料。
