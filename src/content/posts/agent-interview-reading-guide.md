Agent 相关岗位涉及应用开发、模型训练和基础设施，准备时不必试图一次覆盖所有方向。对于有后端开发经验的读者，可以先围绕实际项目，把业务问题、系统运行过程和故障处理讲清楚，再逐步扩展到评测和系统设计。

这篇是阅读导引，参考了 Liuliming 的 [《2025–2026 国内大厂 Agent 面经：从 RAG 到 Harness Engineering》](https://keepkeen.github.io/blog/china-agent-interview-guide-2025-2026/)。原文包含公开资料的来源与证据分级，建议结合原文查看；具体岗位要求和面试问题会随团队与时间变化。

## 先从一个项目出发

选择一个自己真正参与的场景，按以下顺序准备：

1. **目标与边界**：用户遇到什么问题，系统负责处理到哪一步？
2. **运行过程**：用户请求怎样进入系统，模型何时选择工具，结果如何返回？
3. **个人贡献**：自己设计或实现了哪些部分，哪些能力来自已有平台或其他团队？
4. **效果与不足**：用什么方法评估结果；如果没有可靠指标，就明确说明。

## 重点理解工具调用

学习时可以画出一次完整调用：用户请求进入系统后，应用准备上下文和可用工具；模型生成调用意图；程序校验参数并执行工具；工具结果再交给模型或业务流程处理。具体顺序与实现应以实际系统为准。

面试中除了说明正常路径，还应想清楚：工具超时怎么办？参数不合法怎么办？重复调用是否会产生副作用？失败后如何记录、重试或交给人工处理？

## 将知识点串成体系

| 主题 | 可以追问的问题 |
| --- | --- |
| 上下文与记忆 | 当前请求需要哪些信息？历史内容什么时候需要筛选或压缩？ |
| 工具与 Skill | 工具提供什么能力？调用规范、业务流程和执行权限分别由谁负责？ |
| 知识检索 | 什么问题适合检索？如何判断召回内容是否有用？ |
| 评测 | 如何构造测试样本、定义成功标准，并分析失败案例？ |
| 安全与可靠性 | 权限、输入校验、超时、重试和人工确认如何配合？ |

这些问题没有适用于所有系统的统一答案。准备时最好结合项目中的真实设计，区分已经实现的能力、合理推测以及未来的改进方案。

## 建议的阅读顺序

先把项目讲清楚，再学习工具调用和错误处理，然后补充检索、上下文管理与评测。读到不熟悉的概念时，优先回到官方文档或相关项目源码确认，不把转载汇总直接当成事实。
